## 2. 비교 평가 (skill-creator 방식)

조건은 다음과 같다.

- 4개 eval, 구성마다 새 하위 에이전트(Opus 5.5)로 1회씩 실행했다. 오늘 날짜는 2026-10-02로 알려 줬다.
- eval 1·2는 실습 기사 묶음을 실행 폴더에 복사해 줬다. 정답표에는 접근할 수 없게 했다.
- eval 4는 실제 웹 검색이다.
- 채점은 `tools/grade_collector_runs.py`가 맡았다.
  - 결과 형식에 기대지 않고 채점했다. 출처 표시는 번호·URL·"출처"·매체명 괄호 중 무엇이든 인정했다.
  - [판단] 항목 18개는 결과와 최종 응답을 읽고 판정했다(`judgments.json`).

| 1 | 기사 묶음으로 최근 3개월 트렌드 보고서(웹 검색 금지) | **1.00** | 0.73 |
| 2 | 같은 기사로 "바른식품 주식 사도 될까?" | **1.00** | 0.78 |

### v1.6.1이 놓친 것(채점 근거)

| eval | 항목 | v1.6.1 결과 |
|------|------|-------------|
| 1 | 기사에 없는 숫자 | 계산 표시 없는 계산값 7개: "+80%", "+54%·연평균 24%", 차이 "3,000억 원", 역산 "2,650억 원" 등 |

| 4 | 숫자마다 출처 | 13개 중 12개 블록에 출처 표시 없음(출처는 끝에 목록으로만) |
| 4 | 논조 비율 | "긍정 15.8%, 부정 10.5%, 중립 73.7%" |

v1.6.1 실행에서 에이전트가 직접 보고한 스킬 문제는 다음과 같다(결과 보고서 기준).

- `report_generator.py`의 결과가 "분석 필요" 자리표시만 있는 뼈대라, 보고서 eval 3번 모두 손으로 다시 썼다.
- analyzer 센티먼트가 원가·둔화 표현을 몰라 부정을 0%로 셌다(eval 1·2).
- 모드 2 패키지에 다음 결함이 있었다. 에이전트가 직접 고쳐서 점수에는 드러나지 않았다.
  - 수집 소스가 비어 있어(빈 RSS URL, NewsAPI 꺼짐) 그대로면 매일 0건을 보낸다.
  - 워크플로에 커밋 권한이 없다.
  - Slack 단계의 조건이 항상 거짓이다.
  - RSS 날짜를 해석하지 못한다.
- 컨테이너 전용 경로를 쓸 수 없어 매번 우회했다.

eval 3 점수가 같은 것은 두 구성 모두 에이전트가 결과물을 고쳐 완성했기 때문이다. v1.6.1 쪽은 6분 이상 더 걸렸고(449초 대 195초) 패키지 대부분을 다시 썼다.

## 3. 채점기 수정 — 결과를 본 뒤에 바꾼 것

결과를 읽으며 채점기의 오판을 찾아 고쳤다. 모두 두 구성에 같게 적용했다.

| 오판 | 수정 | 점수 영향 |
|------|------|-----------|
| 구글 뉴스 주소가 줄바꿈·변수로 나뉘면 한국어 소스로 못 읽음 | 여러 줄 검색, 설정 파일의 `hl: ko`도 인정 | v1.6.1 eval 3 +1, v2 eval 3 +1 |
| "2025.11", "2025.3Q" 같은 날짜를 숫자로 판정 | 날짜 표기로 처리(스킬 `numparse.py`도 같이 수정) | 주로 v1.6.1에 유리 |
| "1조 5,000억"(원 생략)과 "1조 5,000억 원"을 다른 숫자로 판정 | 큰 단위 금액은 '원' 유무를 같게(스킬도 같이 수정) | v2 eval 1 |
| "(계산: 27÷15)"처럼 계산이라고 밝힌 값을 지어낸 숫자로 판정 | 계산 표시(계산:·(계산)·÷)가 있는 문장은 기사 대조에서 제외 | v2 eval 1·2, v1.6.1 eval 2 |
| "매수·매도 추천을 하지 않습니다"를 면책 고지로 못 읽음 | 고지 표현 확대(스킬 `verify_report.py`도 같이 수정) | v1.6.1 eval 2 +1 |

계산 표시 제외 규칙은 v2 스킬이 가르치는 형식과 같다. 그래서 v2에 유리하게 작용한다. 표시만 붙이면 v1.6.1 결과도 같은 규칙으로 통과한다.
이 수정 전 점수는 다음과 같았다. 수정 후에도 순위는 같다.

| | v2 | v1.6.1 |
|---|:--:|:--:|
| 판단 항목 제외 객관 점수(수정 전) | 24/27 | 19/27 |
| 같은 항목(수정 후) | 27/27 | 21/27 |

## 5. 남은 것

- **content-research 통합(D1)**: 계획서 권장안은 수집 엔진을 data-collector로 모으고 content-research를 콘텐츠 기획 전용으로 줄이는 것이다. 이번 범위에 넣지 않았다. content-research는 아직 Anthropic API를 다시 호출한다(H13).
- **트리거 실측**: CLI 로그인이 필요하다(H10).
- **표본**: 실행 1회씩이고, eval 4는 실제 웹이라 다시 돌리면 결과가 달라진다.
- **키워드 모호성**: "제로슈거 음료" 실제 수집 결과의 대부분이 제로슈거 소주 광고였다. 패키지는 키워드를 바꾸라고 안내만 하고, 의미 필터는 없다.
- **사람 검토용 정적 뷰어**: `.workspace/data-collector-workspace/iteration-1/review.html`(로컬, 커밋 대상 아님).
